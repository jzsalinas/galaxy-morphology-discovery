# OC3 Source-Metadata Autonomous Recovery Production Specification 004

This prospective specification applies only to Run-003. Run-003 uses the
dedicated factory, governor, supervisor, worker, runner, permit root, ledger
root and runtime root bound by Policy Core Manifest 003. Run-001 and Run-002
operational artifacts are read-only predecessors and cannot satisfy any
Run-003 execution gate.

First Candidate 003 is the sole reviewed input candidate. It treats the
immutable Run-002 G01 terminal as diagnostic parent evidence and proposes the
frozen `OFFICIAL_SERVICE_DOCUMENTARY_PROBE`; it does not repeat G01 or promote
its body into scientific metadata. Later candidates are factory-derived under
the Run-003 ledger namespace.

All candidate, authorization, permit, state, output and capability paths use
the canonical repository-relative/derived-absolute identity pair. Candidate
construction and validation must agree from every cwd. Symlink traversal,
repository escape, alias disagreement and copied candidate paths fail closed.

The standing authorization path is reserved but absent. Before a future
mission run, a separate human-reviewed artifact must bind Policy Core Manifest
003, Candidate 003, Waiting State 003, both implementation aggregates, the
Run-002 closure, all unchanged authorities, and the exact mission-runner
command. Candidate 003 grants no authority by itself.

Technical and material counters reset only because the frozen budget is
mission-local. Their exact Run-003 initial values are 8/2,097,152 and
5/67,108,864 respectively. Historical requests remain recorded in the Run-002
closure. Concurrency is 1 and retries are 0 for both classes.

The bounded self-repair policy is available only after standing authorization:
two episodes per mission, one per defect class, zero drift in every protected
domain, no recursive policy mutation and mandatory fresh downstream bindings
after an implementation identity change. Any unmet eligibility condition has
terminal precedence and yields `STOP_REQUIRES_HUMAN`.
