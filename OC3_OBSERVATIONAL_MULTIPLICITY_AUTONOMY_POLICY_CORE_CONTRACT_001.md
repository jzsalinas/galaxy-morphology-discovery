# OC3 Observational Multiplicity Autonomy Policy Core Contract 001

## Purpose

This mission-specific policy core decides only whether an action fits the reviewed observational-multiplicity mandate. Scientific truth remains the responsibility of frozen action specifications and validators.

The core supports exact standing-authorization activation, closed action contracts, one pending action, deterministic single-use permits, permit consumption before material access, bounded completion transitions, STOP, and one of the four mission terminals.

## Immutability

The policy-core manifest binds this contract and both governor implementation files by path and SHA-256. A future standing authorization must bind the exact manifest, mandate, waiting state, branch, and first candidate. Once active, any bound-member mismatch produces `POLICY_CORE_MISMATCH` and requires `STOP_REQUIRES_HUMAN`.

The completed PHOTSYS governor, mandate, authorization, state, ledger, and policy core are historical and are neither reused nor modified.

## Action contract

Every material action uses `OC3_OBSERVATIONAL_MULTIPLICITY_ACTION_CONTRACT_001`. It binds the exact candidate payload, action-validation receipt, stage/scope, command, implementation aggregate, specification, authority classes, reservations, firewall, prohibited scopes, Git branch, resume rule, permit path, and mandate.

Offline local-authority analysis remains epistemically material. It therefore requires a permit even when request and body-byte reservations are zero.

## Failure boundary

No standing authorization means no permit. PHOTSYS reads or reinterpretation, uncontracted source/Tractor values, pixels, morphology labels, representation learning, Panel V3 before its strategy gate, P1, destructive evidence handling, policy mutation, budget expansion, or changed criteria require `STOP_REQUIRES_HUMAN`.
